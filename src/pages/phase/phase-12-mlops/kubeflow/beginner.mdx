## Running ML pipelines on Kubernetes

**Kubeflow** is a set of tools for running machine learning workloads on
Kubernetes — the same infrastructure many companies already use to run their
applications. Instead of writing a shell script to train a model, you write a
**pipeline**: a series of steps, each running in its own container, that
Kubernetes schedules onto available machines (including GPU nodes).

The most commonly used piece is **Kubeflow Pipelines**, which lets you define
a training workflow in Python and get a visual DAG, automatic retries, and
artifact tracking, all running on a Kubernetes cluster.

### Your first pipeline

```python
from kfp import dsl

@dsl.component
def preprocess(input_path: str, output_path: str):
    import pandas as pd
    df = pd.read_csv(input_path)
    df = df.dropna()
    df.to_csv(output_path, index=False)

@dsl.component
def train_model(data_path: str) -> str:
    # ... train and save a model ...
    return "model.pkl"

@dsl.pipeline(name="simple-training-pipeline")
def my_pipeline(input_path: str = "data/raw.csv"):
    prep_task = preprocess(input_path=input_path, output_path="data/clean.csv")
    train_task = train_model(data_path=prep_task.outputs["output_path"])
```

Each `@dsl.component` becomes its own container. Kubeflow figures out that
`train_model` depends on `preprocess`'s output and runs them in the right
order — you never manually manage which machine runs what.

Because every step runs in its own container on Kubernetes, a step that needs
a GPU can request one, while a lightweight preprocessing step runs on a cheap
CPU node — Kubernetes handles the scheduling for you.

```python
from kfp import dsl

@dsl.component
def download_data(output_path: str):
    ...

@dsl.component
def validate_data(input_path: str):
    ...

@dsl.pipeline(name="download-and-validate")
def my_pipeline():
    download_task = download_data(output_path="data/raw.csv")
    validate_data(input_path=download_task.outputs["output_path"])
```
