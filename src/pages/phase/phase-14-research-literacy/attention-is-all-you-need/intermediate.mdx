## Scaled dot-product attention

Every word (token) is projected into three vectors: a **query** (what am I looking
for?), a **key** (what do I contain?), and a **value** (what do I actually
communicate if selected?). Attention is computed as:

```
Attention(Q, K, V) = softmax(Q Kᵀ / sqrt(d_k)) V
```

- `Q Kᵀ` computes a similarity score between every query and every key — how much
  should token *i* attend to token *j*.
- Dividing by `sqrt(d_k)` (the key dimension) keeps the dot products from growing too
  large as dimensionality increases, which would push softmax into regions with
  near-zero gradients.
- `softmax` turns the scores into a probability distribution per query.
- Multiplying by `V` produces a weighted blend of every token's value vector,
  weighted by relevance.

```python
import numpy as np

def scaled_dot_product_attention(Q, K, V):
    d_k = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d_k)          # (seq_len, seq_len)
    weights = np.exp(scores) / np.exp(scores).sum(axis=-1, keepdims=True)
    return weights @ V                        # (seq_len, d_v)
```

## Multi-head attention

Instead of computing attention once with the full dimensionality, the model splits
`Q`, `K`, `V` into `h` smaller "heads", runs attention independently in each, and
concatenates the results. Each head can specialize — one might track syntactic
agreement, another coreference, another local word order — and the model learns
these specializations from data rather than being told what to look for.

```python
def multi_head_attention(Q, K, V, num_heads):
    d_model = Q.shape[-1]
    d_k = d_model // num_heads
    heads = []
    for h in range(num_heads):
        Qh = Q[:, h * d_k:(h + 1) * d_k]
        Kh = K[:, h * d_k:(h + 1) * d_k]
        Vh = V[:, h * d_k:(h + 1) * d_k]
        heads.append(scaled_dot_product_attention(Qh, Kh, Vh))
    return np.concatenate(heads, axis=-1)
```

## Positional encoding

Because there's no recurrence or convolution, the model has no inherent sense of
word order — attention treats the input as a *set*, not a sequence. The paper fixes
this by adding a **positional encoding** (sinusoidal functions of different
frequencies) directly to each token's embedding before the first layer, giving the
model a way to distinguish "position 3" from "position 30" without any recurrence.

## The encoder-decoder stack

The original Transformer is built for machine translation, so it has two stacks:
an **encoder** that reads the source sentence with self-attention, and a
**decoder** that generates the target sentence, using self-attention over what
it's generated so far (masked so it can't look ahead) plus cross-attention over the
encoder's output.

Each encoder/decoder layer also wraps its sub-layers in a residual connection and
layer normalization (`LayerNorm(x + Sublayer(x))`), which is what makes it
practical to stack 6, 12, or (in modern LLMs) 100+ of these layers without training
collapsing.

## What survived into modern LLMs

Most modern decoder-only LLMs (GPT, LLaMA) drop the encoder entirely and use only
the masked self-attention decoder stack — but the core scaled dot-product
multi-head attention block, residual connections, and layer norm are essentially
unchanged from this paper. What has changed is largely around the edges:
sinusoidal positional encoding has mostly been replaced by RoPE or ALiBi, and
LayerNorm placement has shifted from post-norm to pre-norm for training stability
at scale.
