## What the paper actually contributed vs. prior work

Neither RMSNorm, SwiGLU, nor RoPE originated with LLaMA — each had already been
proposed and validated individually in earlier papers. LLaMA's contribution was
threefold: (1) combining these components into one coherent, well-tuned recipe;
(2) applying the Chinchilla scaling-law insight *inverted* — optimizing for
inference-time cost rather than training-time compute, and demonstrating this
concretely by training smaller models on far more tokens than Chinchilla-optimal
and showing they beat much larger contemporaries; and (3) releasing the weights
(initially gated to researchers, fully open with subsequent versions), which
had a bigger ecosystem impact than either of the technical contributions alone.
Before LLaMA, "frontier-adjacent" capability was accessible only through paid
APIs from a handful of labs; after LLaMA, it was a downloadable checkpoint.

## Limitations

- **Training data contamination and licensing ambiguity.** Training on broad
  scraped web data (Common Crawl, GitHub, Books) raised persistent copyright and
  benchmark-contamination questions that the field still hasn't fully resolved.
- **Original release was gated, not fully open.** The first LLaMA's weights
  leaked publicly within days of the restricted research release, which is
  actually how much of the initial "open-source LLM" ecosystem (Alpaca, Vicuna)
  got started — an unplanned rather than intentional openness.
  Llama 2 (2023) course-corrected with a genuinely open (if not OSI-standard)
  commercial license.
- **No instruction-tuning or RLHF in the base model.** The original LLaMA is a
  raw pretrained model — it completes text, but wasn't trained to follow
  instructions or refuse harmful requests. That had to be added downstream, and
  much of the open-source ecosystem's early energy went into exactly that
  (Alpaca fine-tuned it on instruction data generated by GPT-3.5; Vicuna
  fine-tuned it on shared conversations).
- **English-centric.** The training data skewed heavily English, leaving
  substantial quality gaps in other languages relative to closed multilingual
  models of similar or smaller size.

## What came after

- **Alpaca and Vicuna (2023)** showed that instruction-tuning a LLaMA base
  model on a comparatively small amount of instruction data (generated by a
  stronger model, in Alpaca's case) produced surprisingly capable assistants —
  cheaply — kicking off a wave of "distill a big closed model into a small
  open one" research.
- **Llama 2 and Llama 3** scaled the same recipe up (more data, longer context,
  grouped-query attention for cheaper inference, and — for Llama 2 — RLHF-based
  chat tuning shipped directly by Meta) and moved to a genuinely permissive
  license, cementing LLaMA as the default base for open fine-tuning.
- **QLoRA (see the QLoRA lesson)** was demonstrated specifically on LLaMA
  models, making it practical to fine-tune even the 65B variant on a single
  consumer-class GPU — directly enabling the explosion of community fine-tunes.
- **The broader open-weight ecosystem** (Mistral, Qwen, DeepSeek, Kimi) adopted
  LLaMA's RMSNorm/SwiGLU/RoPE block as a starting convention, treating the
  paper's architecture choices as a solved sub-problem rather than something to
  re-derive.

## How it's actually used in production today

Few production systems run the original 2023 LLaMA weights directly anymore —
they've been superseded by Llama 2, Llama 3, and non-Meta open models built on
the same architectural template. But LLaMA's real legacy is structural: it
established that a capable, openly-released base model could be fine-tuned by
downstream teams for their own use case far more cheaply than training from
scratch, and normalized self-hosting LLMs for cost, privacy, or customization
reasons. Every self-hosted open-weight deployment today — on-premises for data
privacy, fine-tuned for a narrow domain, or run on edge hardware — traces its
practical lineage to the ecosystem LLaMA's release kicked off.

## Comparison: closed API model (GPT-3-era) vs. open-weight LLaMA-style model

| Dimension | Closed API model | Open-weight LLaMA-style model |
|---|---|---|
| Access to weights | No — inference only, via API | Yes — full checkpoint download |
| Customization | Limited to prompting / vendor fine-tuning APIs | Full fine-tuning, quantization, architecture inspection |
| Data privacy | Data leaves your infrastructure | Can be fully self-hosted |
| Cost model | Pay per token, ongoing | Upfront compute (or hosting) cost, no per-token vendor fee |
| Optimized for | Training-compute efficiency (historically) | Inference-cost efficiency, given fixed usage volume |
| Ecosystem effect | Single vendor controls capability access | Enabled a broad fine-tuning and research ecosystem |
