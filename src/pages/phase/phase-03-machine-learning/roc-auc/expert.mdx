## The statistical interpretation

AUC has an exact probabilistic meaning: it equals the probability that a randomly chosen
positive example is ranked higher (assigned a higher score) than a randomly chosen negative
example. This is mathematically equivalent to the **Mann-Whitney U statistic** applied to
the two score distributions:

```python
import numpy as np
from sklearn.metrics import roc_auc_score

# Direct Monte Carlo verification of the ranking-probability interpretation
def auc_via_ranking_probability(y_true, scores, n_trials=100_000, seed=0):
    rng = np.random.default_rng(seed)
    y_true = np.asarray(y_true)
    scores = np.asarray(scores)
    pos_scores = scores[y_true == 1]
    neg_scores = scores[y_true == 0]

    pos_sample = rng.choice(pos_scores, n_trials)
    neg_sample = rng.choice(neg_scores, n_trials)
    wins = (pos_sample > neg_sample).sum() + 0.5 * (pos_sample == neg_sample).sum()
    return wins / n_trials

print(auc_via_ranking_probability(y_test, probs))
print(roc_auc_score(y_test, probs))
# Both numbers converge to the same value
```

This is exactly why AUC is threshold-independent: it's a statement about the *ordering* the
model imposes on the whole population, not about any single decision boundary carved out of
that ordering.

## Why ROC-AUC can mislead under severe imbalance

The false positive rate is `FP / (FP + TN)` — normalized by the size of the negative class.
When negatives vastly outnumber positives (fraud, rare disease, intrusion detection), even a
large absolute count of false positives is a small fraction of a huge negative pool, so FPR
stays low and the ROC curve looks good almost regardless of how the minority class is
actually handled.

Concretely: with 10,000 negatives and 100 positives, 500 false positives is only a 5% FPR —
sounds fine on a ROC curve — but if the model only produced 100 total positive predictions
to catch those, precision on the positive class would be under 20%. **Precision-Recall
AUC** doesn't have this blind spot, because precision's denominator (`TP + FP`) is anchored
to the model's own positive predictions, not the size of the negative class:

```python
from sklearn.metrics import roc_auc_score, average_precision_score

print(f"ROC-AUC: {roc_auc_score(y_test, probs):.3f}")           # can look great
print(f"PR-AUC:  {average_precision_score(y_test, probs):.3f}")  # more honest under imbalance
```

## Trade-off summary

| Metric | Normalizes against | Sensitive to imbalance? | What it answers |
|---|---|---|---|
| ROC-AUC | Negative class size (via FPR) | Can look optimistic when negatives dominate | How well does the model rank positives above negatives overall? |
| PR-AUC (Average Precision) | The model's own positive predictions (via precision) | More sensitive — directly reflects false-positive burden relative to true positives | How well does the model rank positives above negatives, weighted toward positive-class performance? |
| F1 (at a threshold) | Neither — fixed operating point | Depends entirely on chosen threshold | Balance of precision and recall at one specific cutoff |
| Accuracy | Total sample count | Highly misleading under imbalance | Overall fraction correct, unweighted by class importance |

## Production concerns

Reporting a single ROC-AUC (e.g. `0.97`) for a fraud or rare-event model to stakeholders
can create a false sense of readiness — the number can be genuinely excellent while the
model is still impractical at any threshold that keeps the false-positive review queue
manageable. The standard mitigation is to always pair ROC-AUC with **PR-AUC and a concrete
confusion matrix at the actual deployed threshold** when communicating model quality,
rather than letting a single high-level ranking metric stand in for real-world usability.
This matters most exactly in the domains where ROC-AUC is most likely to be reported in the
first place — severely imbalanced binary classification — which is precisely where its
optimistic bias under imbalance is strongest.
