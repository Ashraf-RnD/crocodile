## Recall in a real workflow

`recall_score` is rarely used in isolation — it's one metric you pull
alongside precision, F1, and a confusion matrix when evaluating a
classifier:

```python
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import recall_score, classification_report

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42
)

clf = LogisticRegression(max_iter=1000).fit(X_train, y_train)
y_pred = clf.predict(X_test)

print(recall_score(y_test, y_pred))
print(classification_report(y_test, y_pred))
```

## Multiclass recall and `average`

For binary classification, `recall_score` reports recall for the positive
class by default. For multiclass problems, you must choose how to combine
per-class recall values with the `average` parameter:

```python
from sklearn.metrics import recall_score

# y_true / y_pred have classes: 0, 1, 2
recall_score(y_test, y_pred, average="macro")     # unweighted mean across classes
recall_score(y_test, y_pred, average="weighted")   # weighted by class support
recall_score(y_test, y_pred, average="micro")      # aggregate TP/FN globally
recall_score(y_test, y_pred, average=None)         # per-class array, no averaging
```

- `macro` treats every class equally, regardless of how rare it is — good
  when you care about minority-class performance just as much as the
  majority class.
- `weighted` accounts for class imbalance by weighting each class's recall
  by its support — better reflects overall dataset performance.
- `micro` pools all TP/FN counts across classes before dividing, which
  effectively equals accuracy for single-label multiclass problems.

## When recall should drive the decision

Some problems are asymmetric: a false negative is far more expensive than
a false alarm.

- **Medical screening** — missing a cancer diagnosis (false negative) can
  cost a life; a false positive just means a follow-up test.
- **Fraud detection** — letting a fraudulent transaction through
  (false negative) costs money directly; flagging a legitimate transaction
  for review (false positive) costs a bit of customer friction.
- **Security threat detection** — missing an intrusion (false negative)
  can compromise a whole system; a false alarm just wastes an analyst's
  time investigating.

In all three, you deliberately accept more false positives in exchange for
catching more true positives.

## Threshold tuning to boost recall

Most classifiers don't just output a label — they output a probability,
and the 0.5 cutoff is just a default. Lowering the threshold makes the
model label more cases as positive, which raises recall (you catch more
true positives) at the cost of precision (you also let in more false
positives):

```python
import numpy as np
from sklearn.metrics import recall_score, precision_score

probs = clf.predict_proba(X_test)[:, 1]

for threshold in [0.5, 0.3, 0.2, 0.1]:
    y_pred_at_t = (probs >= threshold).astype(int)
    r = recall_score(y_test, y_pred_at_t)
    p = precision_score(y_test, y_pred_at_t)
    print(f"threshold={threshold:.1f}  recall={r:.2f}  precision={p:.2f}")

# threshold=0.5  recall=0.62  precision=0.81
# threshold=0.3  recall=0.78  precision=0.64
# threshold=0.2  recall=0.89  precision=0.51
# threshold=0.1  recall=0.97  precision=0.34
```

As the threshold drops, recall climbs toward 1.0 but precision erodes —
you're trading false alarms for fewer misses.

## Common pitfall: gaming recall

Recall alone is easy to game: predict positive for every single example
and you get 100% recall trivially, since there are no false negatives at
all.

```python
# The "predict everyone has the disease" model
y_pred_naive = [1] * len(y_test)
print(recall_score(y_test, y_pred_naive))  # 1.0 — perfect recall, useless model
```

That's why recall is almost never reported alone in practice. Pair it with
precision (or F1, which balances the two) and look at the confusion
matrix directly — a model with perfect recall and near-zero precision has
learned nothing useful.
