## Naive Bayes: a whole classifier built on this one formula

A Naive Bayes classifier predicts the class `C` that maximizes `P(C | features)`,
using Bayes' theorem to flip it into things you *can* estimate from training data:

```
P(C | x1, x2, ..., xn) ∝ P(C) · P(x1 | C) · P(x2 | C) · ... · P(xn | C)
```

The "naive" part is assuming features are conditionally independent given the class
(from the previous lesson) — this lets you estimate each `P(xi | C)` separately from
counts in your training data, instead of needing the full joint distribution, which
would require exponentially more data.

```python
import numpy as np

# toy estimates learned from training data (word frequencies per class)
p_spam = 0.3
p_word_given_spam = {"free": 0.6, "meeting": 0.05}
p_word_given_ham = {"free": 0.05, "meeting": 0.3}

def score(words, p_class, p_word_given_class):
    p = p_class
    for w in words:
        p *= p_word_given_class.get(w, 0.01)  # small default for unseen words
    return p

email = ["free"]
spam_score = score(email, p_spam, p_word_given_spam)
ham_score = score(email, 1 - p_spam, p_word_given_ham)
print("spam" if spam_score > ham_score else "ham")
```

## Bayesian updating: priors evolve with evidence

Bayes' theorem naturally supports *sequential* updating: yesterday's posterior becomes
today's prior. This is the conceptual foundation of Bayesian A/B testing and Bayesian
hyperparameter optimization (e.g. Gaussian Process-based tools like Optuna's TPE
sampler) — each new observation refines a belief distribution rather than producing a
single point estimate, which naturally captures uncertainty alongside the estimate.

## Why "smoothing" matters (Laplace/additive smoothing)

If a word never appeared in training spam emails, `P(word | spam) = 0`, which zeroes
out the entire product regardless of other evidence — one unseen word can override
everything else. **Laplace smoothing** adds a small constant to every count so no
probability is ever exactly zero:

```python
def smoothed_prob(count, total, vocab_size, alpha=1):
    return (count + alpha) / (total + alpha * vocab_size)
```
