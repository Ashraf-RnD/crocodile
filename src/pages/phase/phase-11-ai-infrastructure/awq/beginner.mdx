## Protect the important 1%, crush the rest

Imagine packing a suitcase where most items can be squished flat, but a handful
(your glasses, a camera) will break if compressed. You don't treat everything the
same — you protect the fragile few and squish everything else hard. **AWQ**
(Activation-aware Weight Quantization) does exactly this to a neural network's
weights: it finds the small fraction of weight channels that matter most (based on
how large the *activations* flowing through them tend to be, not the weight values
themselves), protects those, and then quantizes everything — protected and
unprotected alike — down to 4-bit. The result is a model that's ~4x smaller with
surprisingly little accuracy loss.

This matters because most of a 4-bit model's accuracy damage comes from a small
number of "salient" channels getting crushed. Leave those relatively unharmed, and
the aggressive 4-bit rounding on everything else barely shows up in the output.

## Using an AWQ model

You don't need to quantize anything yourself to benefit — most popular models
already have pre-quantized AWQ versions on Hugging Face. Serving one with vLLM:

```bash
vllm serve TheBloke/Mistral-7B-Instruct-v0.2-AWQ --quantization awq
```

Or loading one directly with AutoAWQ / Transformers in Python:

```python
from transformers import AutoModelForCausalLM, AutoTokenizer

model_id = "TheBloke/Mistral-7B-Instruct-v0.2-AWQ"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(model_id, device_map="auto")

inputs = tokenizer("Explain quantization in one sentence:", return_tensors="pt").to(model.device)
output = model.generate(**inputs, max_new_tokens=40)
print(tokenizer.decode(output[0], skip_special_tokens=True))
```

Same API as loading a full-precision model — the weights just take a quarter of
the GPU memory, which is often the difference between a model fitting on your GPU
or not.

## Why "activation-aware" and not just "weight-aware"

A weight with a small value might still matter enormously if it's always multiplied
by a huge activation — the product is what flows through the network. AWQ looks at
activation statistics (gathered by running a small calibration dataset through the
model) to find which weight *channels* consistently see large activations, and
treats those as salient — regardless of how big the raw weight numbers look.

## Try it yourself

Two weight channels have identical average magnitude. Channel A is multiplied by
activations that are usually near zero. Channel B is multiplied by activations that
are consistently large. Which channel should AWQ protect more carefully during
quantization, and why?

<details>
<summary>Solution</summary>

Channel B — even though the raw weight magnitudes are the same, channel B's
contribution to the layer's output (weight × activation) is much larger in
practice. Rounding error introduced there does more damage downstream than the
same rounding error on channel A, whose small activations mean its errors barely
register. This is the core insight behind "activation-aware" salience.
</details>
