## Installing code someone else already wrote

Almost no AI project starts from scratch — you install libraries like `numpy`,
`torch`, or `transformers` and build on top of them. **pip** is Python's default
package installer: it downloads a package from PyPI (the Python Package Index) and
puts it somewhere your `import` statements can find it.

```bash
pip install numpy
pip install torch transformers   # install multiple at once
pip install pandas==2.2.0        # a specific version
pip uninstall pandas
pip list                         # see what's installed
```

### `requirements.txt`: sharing what your project needs

Instead of telling teammates to run five separate `pip install` commands, projects
list their dependencies in a text file.

```
# requirements.txt
numpy==1.26.4
pandas==2.2.1
scikit-learn==1.4.0
```

```bash
pip install -r requirements.txt   # installs everything listed, at those versions
```

This is how you reproduce someone else's environment — clone their repo, run one
command, get the same libraries at the same versions they used.

### Why a virtual environment matters

Installing packages "globally" means every project on your machine shares the same
package versions — and one project needing `numpy==1.20` while another needs
`numpy==2.0` becomes impossible to satisfy at once. A **virtual environment** gives
each project its own isolated set of installed packages.

```bash
python -m venv .venv        # create an isolated environment in ./.venv
source .venv/bin/activate   # activate it (Windows: .venv\Scripts\activate)
pip install numpy           # installs into .venv, not globally
deactivate                  # leave the environment
```
