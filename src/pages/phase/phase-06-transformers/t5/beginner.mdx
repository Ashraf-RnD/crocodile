## T5's big idea: everything is text-to-text

BERT is great at understanding, GPT is great at generating — but they're set up
differently for different tasks (classification heads for BERT, plain generation for
GPT). T5 (Text-to-Text Transfer Transformer) proposes something simpler: **treat
every NLP task as converting one piece of text into another piece of text.**

- Translation: `"translate English to German: The house is wonderful."` → `"Das Haus ist wunderbar."`
- Summarization: `"summarize: <long article>"` → `"<short summary>"`
- Classification: `"cola sentence: The dog barks loudly."` → `"acceptable"`
- Even regression-like tasks (similarity scoring) get converted to text: → `"3.8"`

Every task, no matter how different it seems, becomes "read this text prefix + input,
write out the output text." T5 uses a full **encoder-decoder** architecture (like the
original Transformer) — the encoder reads the input, the decoder generates the
output — which is a natural fit for this text-in, text-out framing.

### Trying T5 on a few different "tasks"

```python
from transformers import T5Tokenizer, T5ForConditionalGeneration

tokenizer = T5Tokenizer.from_pretrained("t5-small")
model = T5ForConditionalGeneration.from_pretrained("t5-small")

def run_t5(prompt):
    inputs = tokenizer(prompt, return_tensors="pt")
    outputs = model.generate(**inputs, max_new_tokens=40)
    return tokenizer.decode(outputs[0], skip_special_tokens=True)

print(run_t5("translate English to German: The weather is nice today."))
print(run_t5("summarize: The quick brown fox jumps over the lazy dog. "
             "This sentence is often used to test typefaces because it "
             "contains every letter of the English alphabet."))
```

Notice: it's the exact same model, the exact same `generate()` call — only the text
*prefix* changes to tell the model which task to perform. That's the whole point.

## Try it yourself

Using the same `run_t5` function, write a prompt asking T5 to answer the question
"cola sentence: He go to the store yesterday." (a grammatical-acceptability check —
T5 was trained on this exact task format as part of its multi-task pretraining).

<details>
<summary>Solution</summary>

```python
print(run_t5("cola sentence: He go to the store yesterday."))
# Expected output: "unacceptable" — the sentence has a grammar error
# ("He go" should be "He went"), and T5 was trained on the CoLA
# (Corpus of Linguistic Acceptability) task in exactly this text-to-text format.
```

The key insight: you didn't need a different model, a different output layer, or
even different code — just a different natural-language task prefix. This is what
"text-to-text" as a unifying framework buys you.

</details>
