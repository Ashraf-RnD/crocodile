## BERT's input representation

Every BERT input combines three signals that get summed before entering the encoder
stack:

<Mermaid client:visible code={`flowchart TB
  Tok["Token embeddings ([CLS] the movie was great [SEP])"] --> Sum["Sum"]
  Seg["Segment embeddings (sentence A vs sentence B)"] --> Sum
  Pos["Positional embeddings (learned, per position)"] --> Sum
  Sum --> Enc["12 (base) or 24 (large) encoder layers"]
  Enc --> ClsOut["[CLS] output → classification head"]
  Enc --> TokOut["Per-token output → NER / QA head"]`} />

- `[CLS]` — a special token prepended to every input, whose final hidden state is
  commonly used as a whole-sequence summary for classification.
- `[SEP]` — separates two sentences when BERT is given a sentence-pair input (useful
  for tasks like natural language inference or question answering).
- Segment embeddings tell the model which sentence (A or B) each token belongs to.

## Fine-tuning BERT for classification

The standard production pattern is: load pretrained BERT, add a small classification
head, fine-tune on your labeled data.

```python
from transformers import AutoTokenizer, AutoModelForSequenceClassification, TrainingArguments, Trainer
import torch

tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
model = AutoModelForSequenceClassification.from_pretrained(
    "bert-base-uncased", num_labels=2   # e.g. binary sentiment
)

def tokenize(batch):
    return tokenizer(batch["text"], truncation=True, padding="max_length", max_length=128)

# dataset = your_dataset.map(tokenize, batched=True)   # HF datasets object

training_args = TrainingArguments(
    output_dir="./bert-finetuned",
    per_device_train_batch_size=16,
    num_train_epochs=3,
    learning_rate=2e-5,     # small LR — we're fine-tuning, not training from scratch
    evaluation_strategy="epoch",
)

# trainer = Trainer(model=model, args=training_args, train_dataset=dataset["train"],
#                    eval_dataset=dataset["test"])
# trainer.train()
```

A learning rate around `2e-5` to `5e-5` is standard for BERT fine-tuning — much lower
than you'd use training from scratch, because you're making small adjustments to
already-useful pretrained weights, not learning representations from zero.

## Masked Language Modeling + Next Sentence Prediction (the original recipe)

BERT's original pretraining combined two objectives:

1. **Masked Language Modeling (MLM)** — randomly mask ~15% of tokens and predict
   them from bidirectional context (the mechanism shown at the beginner level).
2. **Next Sentence Prediction (NSP)** — given two sentences, predict whether sentence
   B actually follows sentence A in the original text, or is a random sentence.

NSP was intended to teach sentence-pair relationships useful for tasks like question
answering, but later work (RoBERTa) found it contributed little and often hurt
performance compared to just training MLM longer on more data — a useful reminder
that not every component of an influential architecture turns out to be load-bearing.

## Common downstream tasks BERT is fine-tuned for

| Task | How BERT is adapted |
|---|---|
| Sentiment / topic classification | Linear head on `[CLS]` output |
| Named entity recognition (NER) | Linear head on every token's output |
| Extractive question answering | Two linear heads predicting answer span start/end positions |
| Sentence pair similarity / NLI | `[CLS]` output from a `[SEP]`-joined sentence pair |

## Why BERT specifically, not "just any encoder"

BERT's lasting significance wasn't a novel architecture — it reused the Transformer
encoder essentially unchanged. Its contribution was demonstrating that **large-scale
self-supervised pretraining followed by lightweight task-specific fine-tuning**
produces state-of-the-art results across a wide range of NLP tasks with a single
pretrained checkpoint — a paradigm shift the field had been circling but which BERT
made unambiguous and reproducible at scale.
